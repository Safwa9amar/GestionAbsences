# الفصل الثالث : الجانب التطبيقي

> نص جاهز للإدماج في المذكرة، يصف البرنامج المنجز.

## تمهيد

بعد أن تم في الفصل الثاني تحليل النظام الموجود ودراسة الوثائق والسجلات والإجراءات،
ثم إعداد النموذج المفاهيمي (MCD) والنموذج المنطقي (MLD) للمعطيات، نتناول في هذا الفصل
الجانب التطبيقي، أي تجسيد التصميم في برنامج معلوماتي قابل للاستعمال من طرف
مصلحة مستشار التربية.

## 1. أدوات الإنجاز

| الأداة | الدور | المبرر |
|--------|------|--------|
| **Delphi / Object Pascal** | لغة البرمجة وبيئة التطوير | لغة مهيكلة، بيئة RAD تسمح ببناء الواجهات بسرعة، وتنفيذ مباشر دون آلة افتراضية |
| **Microsoft Access (Jet 4.0)** | نظام تسيير قاعدة البيانات | خفيف، لا يحتاج خادما، متوفر في بيئة المؤسسة، ملف واحد سهل النسخ الاحتياطي |
| **ADO (ActiveX Data Objects)** | واجهة الربط بين البرنامج والقاعدة | تقنية معيارية من Microsoft، مدمجة في Delphi عبر مكونات `TADOConnection` و`TADOQuery` |
| **منهجية MERISE** | التحليل والتصميم | منهجية مهيكلة تفصل بين مستوى المعطيات ومستوى المعالجات |

### بنية التطبيق

```
GestionAbsences.exe
      │
      ├── dmMain  (وحدة المعطيات) ──► TADOConnection ──► Data\GestionAbsences.mdb
      │
      ├── uDB     : إنشاء القاعدة والجداول آليا عند أول تشغيل + النسخ الاحتياطي
      ├── uLang   : كل نصوص الواجهة بالعربية (فصل النص عن الشيفرة)
      ├── uUtils  : خدمات (تجزئة كلمة المرور SHA-1، الرسائل، توليد الوثائق)
      │
      └── الواجهات : تسجيل الدخول، القائمة الرئيسية، التلاميذ، البيانات الأساسية،
                     الغيابات اليومية، التبرير، الإشعارات، الوثائق، التقارير،
                     المستخدمون، الإعدادات
```

اعتُمد نمط **الطبقات الثلاث** :
1. **طبقة العرض** (Forms) : الواجهات الرسومية.
2. **طبقة المعالجة** (dmMain / uDB) : قواعد التسيير وبناء استعلامات SQL.
3. **طبقة التخزين** (Access) : الجداول والقيود.

## 2. أمن النظام

استجابةً للتساؤل المطروح في الإشكالية *«كيف يمكن حماية هذا النظام من المستخدمين
غير المرخص لهم بالولوج لبياناته ؟»* اعتُمدت الإجراءات التالية :

- **مصادقة إجبارية** : لا يمكن بلوغ أي واجهة قبل تسجيل الدخول.
- **تجزئة كلمات المرور** بخوارزمية **SHA-1** : كلمة المرور لا تُخزَّن أبدا بشكل صريح
  في قاعدة البيانات، بل تُخزَّن بصمتها فقط (64 محرفا).
- **ثلاث صلاحيات** : مسؤول النظام (ADMIN)، مستشار التربية (ADVISOR)،
  مشرف التربية (SUPERV). واجهتا *المستخدمون* و*الإعدادات* محجوزتان لمسؤول النظام.
- **قفل الحساب** بعد ثلاث محاولات فاشلة.
- **حماية آخر حساب مسؤول** من الحذف أو التوقيف.
- **تتبع العمليات** : كل غياب يحمل حقل `RecordedBy` و`RecordedAt`.
- **النسخ الاحتياطي والاسترجاع** من القائمة *أدوات*.

## 3. عرض واجهات البرنامج

| الواجهة | الوظيفة | يقابلها في الدراسة |
|---------|---------|--------------------|
| **تسجيل الدخول** | المصادقة وتحديد الصلاحية | — |
| **القائمة الرئيسية** | لوحة قيادة (عدد التلاميذ، الأقسام، غيابات اليوم، الغيابات غير المبررة) + قوائم التنقل | — |
| **تسيير التلاميذ** | إضافة/تعديل/حذف ملف التلميذ، البحث، قائمة القسم، غيابات التلميذ | *استمارة معلومات التلميذ* (جدول 1) |
| **البيانات الأساسية** | المستويات، الأقسام، المواد، الأساتذة، الحصص، السنوات الدراسية | *سجل الدخول والخروج* (جدول 12) |
| **تسجيل الغيابات اليومية** | اختيار التاريخ + القسم + الحصة، ثم تحديد حالة كل تلميذ (حاضر/غائب/متأخر) | *وثيقة غياب التلاميذ* (جدول 8) |
| **تبرير الغيابات** | تبرير غياب أو عدة غيابات دفعة واحدة مع ذكر السبب | *اشعار أول/ثان بالغياب* |
| **الإشعارات والاستدعاءات** | اقتراح آلي للإشعارات حسب العتبات + تحرير وطباعة الوثيقة | *اشعار أول* (جدول 4)، *اشعار ثان* (جدول 6)، *اعذار بالشطب* (جدول 7)، *استدعاء الولي* (جدول 2) |
| **ورقة الدخول** | تسليم رخصة دخول لتلميذ متأخر | *ورقة الدخول* (جدول 9) |
| **الشهادة المدرسية** | تحرير الشهادة بعدد النسخ المطلوب مع ترقيم تسلسلي | *شهادة مدرسية* (جدول 10) و*سجل الشهادة المدرسية* (جدول 11) |
| **التقارير والإحصائيات** | التقرير اليومي، سجل الغيابات، حوصلة حسب القسم، الأكثر غيابا، نسب الحضور | *التقرير اليومي* (جدول 3)، *سجل الغيابات والتأخرات* (جدول 13) |
| **المستخدمون** | إنشاء الحسابات وتحديد الصلاحيات | — |
| **إعدادات المؤسسة** | تسمية المؤسسة، المديرية، المدير، المستشار، وعتبات الإشعار | *البطاقة الفنية للمؤسسة* |

## 4. آلية الاقتراح الآلي للإشعارات

هي القيمة المضافة الأساسية للبرنامج مقارنة بالتسيير اليدوي :

```
لكل تلميذ يزاول دراسته :
    عدد = عدد الغيابات غير المبررة خلال الفترة المختارة
    إذا كان عدد ≥ العتبة 3  →  اقتراح « إعذار بالشطب »
    وإلا إذا كان عدد ≥ العتبة 2  →  اقتراح « إشعار ثان بالغياب »
    وإلا إذا كان عدد ≥ العتبة 1  →  اقتراح « إشعار أول بالغياب »
    شرط ألا يكون نفس النوع قد حُرِّر للتلميذ في نفس الفترة
```

العتبات الافتراضية : **3 / 6 / 10** غيابات غير مبررة، وهي قابلة للتعديل من
واجهة *إعدادات المؤسسة* حسب النظام الداخلي للمؤسسة.

## 5. حساب نسبة الحضور والغياب

```
الحصص الممكنة  = عدد تلاميذ القسم × أيام العمل × عدد الحصص في اليوم
نسبة الغياب %  = (ساعات الغياب ÷ الحصص الممكنة) × 100
نسبة الحضور %  = 100 − نسبة الغياب
```

*أيام العمل* تُحسب بين التاريخين باستثناء يومي الجمعة والسبت.

## خلاصة

مكّن هذا الفصل من تجسيد التصميم النظري في برنامج عملي يغطي كامل دورة تسيير
الغيابات : من تسجيل ملف التلميذ، مرورا بالرصد اليومي للغيابات والتأخرات وتبريرها،
وصولا إلى تحرير الوثائق الرسمية وإنتاج الإحصائيات. وبذلك تتحقق الأهداف المسطرة في
المقدمة : إنشاء قاعدة بيانات خاصة بالمصلحة، تسهيل الحصول على المعلومة، تسهيل متابعة
الملفات، تنظيم الأعمال والحد من الأخطاء، وربح الوقت.
